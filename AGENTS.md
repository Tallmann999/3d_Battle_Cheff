# Правила работы с CHEF SHOW PROTOTYPE

Этот файл подключает существующие документы проекта к следующим сессиям агента. Прямые актуальные указания автора имеют приоритет; статус файла или карточки не доказывает работоспособность игры.

Перед работой читать по порядку:

1. `GAME_CONCEPT.md` — канонический GDD; различать зафиксированные правила, предложения и TBD.
2. `CODEX_PROJECT_INSTRUCTIONS.md` — workflow, правила Unity-assets, структура и поэтапная реализация.
3. `docs/feature-index.md` — единственный изменяемый индекс фич.
4. Карточку текущей фичи из `docs/features/`, `docs/decisions.md`, `docs/architecture.md` и последние записи `docs/implementation-log.md`.
5. Фактические файлы проекта и незавершённые изменения Git.

Автор 2026-10-06 запросил работу через Unity MCP с открытым Editor. Настройка и диагностика: `docs/unity-mcp.md`. Предпочитать MCP для операций со сценой; управление окном не требуется для штатной работы. Перед мутациями читать активный проект, сцену, Play Mode, компиляцию, выделение и dirty-state. Не считать MCP защитой от конфликтов: команды Unity выполняются последовательно, но ручные изменения автора могут попасть между ними. Не править одновременно тот же объект/asset, не закрывать несохранённые сцены и не перезаписывать их сохранённым файлом.

Игровые объекты и MonoBehaviour должны существовать в сохранённой рабочей сцене и быть видны в Hierarchy/Inspector в Edit Mode. Не создавать кухню/участников только при Play, не применять HideFlags для сокрытия игрового контента. Ссылки на конфиги и assets показывать в Inspector; использовать понятные имена и группы. MCP-соединение — служба Editor, не скрытый игровой объект. После изменения объяснять автору, где находятся объекты и как проверить их вручную.

Статус `verified` требует записанного результата нужной проверки в Unity/сборке. Статический осмотр и наличие кода не заменяют Play Mode. После каждого этапа обновлять индекс, карточку и implementation log; сообщать, что игрок может сделать и как это проверить.
