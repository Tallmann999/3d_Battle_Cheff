# F-013 — Экраны, Retry, полный сброс и debug

Дата создания/обновления: 2026-10-05. Приоритет: MVP. Статус: in_progress. Дизайн/приёмка: автор; документация/реализация: Codex. Модель проекта: premium (D-006). Карточка определяет поведение и приёмку; TBD закрываются перед затронутой реализацией.

Текущее состояние: Есть HUD/пауза/чувствительность/restart и debug-таймеры этапа 1. Игровые экраны, Retry Round, полноценные force-команды и приёмка release-сборки впереди.

Связи: [индекс](../feature-index.md), [решения](../decisions.md), [проверки](../test-plan.md), [полный GDD](../../GAME_CONCEPT.md), [инструкция Unity](../../CODEX_PROJECT_INSTRUCTIONS.md). Источники: GDD §8/18; инструкция §4/9/18.

## Проблема, цель и ожидаемый эффект

Сделать прототип доступным для игры и проверки с первого этапа, включая честный повтор после поражения.

Почему сейчас / выбранный объём: Без UI/reset первая механика трудно проверяется, а остатки предыдущей попытки создают ложные баги. Поэтапная интеграция полезнее позднего единого UI-прохода. Критерий успеха — наблюдаемое выполнение acceptance ниже; количественный плейтест интереса оценивается на игровом срезе по GDD §22, а не по наличию файлов.

## Игровое поведение и сценарий

HUD/управление/briefing/пауза/результаты/выбывание/finale/reveal. Retry восстанавливает начало текущего раунда с составом/seed, Restart создаёт чистый выпуск. F1 diagnostics только Editor/Development при разрешённом flag; force overrides видимы.

Первый вход и повтор используют эти же правила; чистый повтор и новые/прежние seeds определяются штатным Restart/Retry, а не визуальной анимацией.

## In / Out / Future

Начало — HUD/пауза/restart; затем screens, настройки чувствительности/тряски/субтитров, debug-команды по инструкции. Нет сохранения попытки на диск или release force-команд.

## Зависимости и место в выпуске

Начало F-001/F-003; экраны и snapshots по текущим фичам F-007…F-012. Полная готовность фичи требует её полного scope; ранняя часть в вертикальном срезе отдельно отмечается в журнале.

## Данные и параметры

subtitle_scale, look_sensitivity, camera_shake_enabled — значения по проверке удобства. prototype_debug_enabled; debug_timer_sec=30/60/240, simulation_speed — диагностика, не обычный баланс.

Значения «старт GDD» являются редактируемыми предложениями. Прямые решения D-001…D-007 имеют приоритет. Невалидные конфиги должны давать понятную диагностику, а не случайный результат.

## События и локальная проверка

ui_pause_requested, retry_round_requested, restart_show_requested, debug_override_applied; выполнение фиксирует фактический результат владельца.

Дизайн-ключи здесь не требуют отдельной строковой системы событий; техническое сопоставление берётся из инструкции. Локальный лог с контекстом/seed достаточен; серверная аналитика не входит в MVP.

## UI и тексты

RU тексты и кириллический asset, контрастные субтитры, A/B плюс цвета; ui_retry_round, ui_restart_show, ui_debug_forced. Экран причин результата позволяет понять поражение.

## Негативные случаи и ограничения

Retry после выбывания/финала, Restart в фокусе/на паузе/во время речи, старые действия/подписки, пропавший font. Меню не исполняет готовочные команды и возвращает верный курсор.

## Acceptance criteria

1. HUD/пауза/restart присутствуют с этапа 1; кириллица читается.
2. Retry восстанавливает начало именно текущего раунда; не сохраняет итог проигрыша.
3. Restart после любого исхода очищает продукты, callbacks, очередь, номера и overrides.
4. Debug не доступен в обычной сборке; forced score/результат явно помечен.
5. Обязательные экраны и настройки из GDD работают без технических пояснений в обычном потоке игрока.

## Способ проверки и анализ

T-003/T-004/T-006/T-018/T-024/T-026; ручные маршруты меню и PlayMode reset.

После проверки записать pass/fail, контекст/seed, ограничения и доказательство в implementation-log, обновить статус в индексе. Если критерий не пройден, исправить затронутую часть перед зависимой фичей; успешный статический осмотр не заменяет Play Mode.
